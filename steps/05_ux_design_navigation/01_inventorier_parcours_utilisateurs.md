# 05.1, inventorier les parcours utilisateurs

## Objectif

Décrire les besoins et parcours du visiteur, du parent et de l’élève sans inventer de logique métier non validée.

## Livrables

Créer sous `docs/ux/` :

- `personas-et-contextes.md` ;
- `parcours-parent.md` ;
- `parcours-eleve.md` ;
- `matrice-besoins-ecrans.md`.

## Parcours minimaux

### Visiteur

- découvrir StudentConnect ;
- comprendre la proposition de valeur ;
- accéder à la connexion ou à l’inscription ;
- consulter les informations légales et d’assistance.

### Parent

- consulter une synthèse familiale ;
- choisir un enfant ;
- voir progression, lacunes et recommandations ;
- consulter les activités et notifications ;
- gérer les paramètres familiaux.

### Élève

- voir un accueil simple ;
- comprendre le prochain objectif ;
- lancer une activité courte ;
- voir une progression compréhensible ;
- recevoir une rétroaction claire et non trompeuse.

## Cas transversaux

- première visite ;
- dossier incomplet ;
- aucune donnée ;
- chargement ;
- erreur réseau ;
- accès refusé ;
- contenu indisponible ;
- session expirée.

## Acceptation

- [ ] Chaque parcours possède un point d’entrée, des étapes et une sortie.
- [ ] Les différences Parent et Élève sont explicites.
- [ ] Les besoins ne sont pas présentés comme déjà implémentés.
- [ ] Les données fictives sont signalées.
